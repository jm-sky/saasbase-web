## Auth / onboarding

### [Auth] Błąd logowania zawsze jako „Invalid credentials”
- **Ekran / URL:** `/login`
- **Obserwacja:** Przy błędzie reCAPTCHA (i innych 4xx) pola e-mail/hasło dostają ten sam komunikat co przy złym haśle; toast też bywa mylący.
- **Wpływ:** średni
- **Kategoria:** copy / flow
- **Propozycja:** Mapować `message` / `error` z API; błędy pól tylko przy 401 / „credentials”.
- **Rozmiar fixu:** S — ✅ **zaimplementowano**

### [Auth] Dev: reCAPTCHA bez skip blokuje lokalny login
- **Ekran / URL:** `/login`
- **Obserwacja:** FE wymaga tokenu reCAPTCHA; bez `RECAPTCHA_SKIP_VERIFY=true` (local) logowanie w dev pada.
- **Wpływ:** wysoki (dev)
- **Kategoria:** flow
- **Propozycja:** `RECAPTCHA_SKIP_VERIFY` w API (local) + dokumentacja w `.env.example`.
- **Rozmiar fixu:** S — ✅ **zaimplementowano (API)**
